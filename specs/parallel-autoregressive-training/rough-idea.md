# Rough Idea: Parallel Autoregressive Training

The current mel-spectrogram generator is being trained autoregressively by repeatedly feeding progressively longer prefixes of the sequence back into the model during training. At timestep *t*, the model receives frames `[0:t]` and predicts frame `t+1`, which is implemented with a Python loop that repeatedly calls the model and concatenates inputs. This approach is extremely inefficient because it forces O(T) forward passes per sequence and prevents TensorFlow from parallelizing computation across timesteps.

The model architecture (a transformer or convolutional sequence model) should instead be trained using **parallel autoregressive training with a causal mask**. In this setup, the entire sequence is passed through the model in a single forward pass, but a **causal attention mask (or causal convolution)** ensures that position *t* can only attend to positions `< t`. This preserves the exact same autoregressive dependency structure used during inference while allowing the model to compute all timesteps simultaneously on the GPU/CPU. Training should therefore operate on full sequences `(batch, seq_len, mel_dim)` with a next-frame prediction objective, typically computing loss between `preds[:, :-1, :]` and `targets[:, 1:, :]`.

Refactor the training pipeline so that the model accepts full sequences with a causal mask rather than growing prefixes during training. Eliminate timestep loops, repeated model calls, and tensor concatenation in the training step. The goal is to preserve autoregressive semantics while enabling fully parallel sequence processing, significantly improving training throughput and making the implementation compatible with standard transformer or causal convolution architectures used in modern mel-spectrogram generation systems.
